# S1 â€” Episode evaluator and training repeatability

## Scientific question

The fixed-scene R002 result showed that Stage 1 can be learned once. S1 asks a
stricter question: does the unchanged task produce a nominal placement policy
for training seeds 42, 43, and 44, and which nearby egg starts does each frozen
policy solve?

S1 changes measurement, not the task. Do not change the robot, observations,
actions, rate limiter, reward, PPO settings, physics, episode length, object
spawn during training, or robot-base motion.

## Evidence produced per checkpoint

`tools/evaluate_stage1.py` writes:

- `episodes.csv`: one row per completed episode;
- `checkpoint.sha256`: exact checkpoint identity;
- `metadata.json`: evaluator/training provenance and dependency identity;
- `summary.json`: checkpoint-level gate result;
- `videos/*.mp4`: the first nominal episode when `--record-video` is used;
- `success_basin.png` and `.svg`: categorical outcomes at the 25 exact grid
  points;
- `manifest.sha256`: hashes of the evidence bundle.

The five nominal rows have the same `physical_condition_id`. They test whether
the computation repeats; they are not five statistically independent physical
trials. The grid contains 25 distinct `physical_condition_id` values. One
deterministic outcome per point maps coverage, not success probability.

## Exit gate and next decision

S1 passes only when all three final checkpoints satisfy all of the following:

1. five of five nominal computational repeats end in strict bucket success;
2. the 25 exact grid outcomes are present;
3. no OOB termination occurs;
4. no NaN termination occurs;
5. no termination predicates overlap;
6. the checkpoint hash and one nominal video are present.

If any seed fails, stop. Diagnose training repeatability while keeping Stage 1
frozen. Do not change reward terms, start spawn randomization, or add base x/y
motion.

If all three pass, S1 is complete. The next experiment is controlled egg XY
spawn randomization during training, with the robot base still fixed. Base x/y
motion remains postponed until the fixed-base success maps show that the task's
required workspace lies outside the robust fixed-base basin.
